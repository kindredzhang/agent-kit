# Rein 实施计划：跨代理用量与共享预算

> 日期：2026-11-26。状态：A0–A5 的基础能力、测试和文档已实施；美元预算和跨进程账本仍属非目标。
> 前置能力：Agent run、工具审批与暂停恢复、追踪、agents-as-tools。

## 1. 目标与范围

让宿主能够观察并限制一次根 Agent run 及其通过 `createSubagentTool` 启动的后代 run 的模型调用。第一批按交付顺序完成：

1. 建立整棵任务树的用量统计，明确各 run 与全树的统计口径。
2. 可选设置共享模型调用次数上限，在请求发出前原子认领名额。
3. 在调用次数控制稳定后，增加可选的共享 token 软上限，明确缺失用量和并行超额语义。
4. 提供预算事件、停止原因、文档和可观测性；保持默认行为兼容。

本批不实现美元预算、工具收费、跨进程或跨机器共享预算、Session 跨多个 run 的累计额度、精确的账单对账，也不承诺取消或失败请求的服务端用量一定可见。价格表、缓存计费、外部工具费和持久化账本留待后续按实际需求设计。

## 3. 领域与统计口径

- **根 run**：宿主直接启动的一次 Agent run。其生命周期内启动的子 run 构成一棵任务树。
- **共享预算**：由同一棵任务树的各 run 共同使用的进程内账本；根 run 创建，子代理自动继承。每次独立根 run 默认创建独立账本，即使复用同一 Agent 或工具实例也不共享。
- **run 用量**：现有 `usage` 语义保持不变，只统计该 run 自己观察到的模型 usage，不包含后代。
- **树用量**：父和各后代每次模型请求观察到的 usage 合计；只能记录 provider 实际报告的字段。未知值不得当作零来声称完整统计，结果应公开完整性状态。
- 模型调用次数在实际进入 `LanguageModel.stream()` 前认领；即使请求失败或取消，已认领次数也不返还。尚未调用模型时取消不消耗名额。
- 同一 provider 请求的 usage 事件可能有多种约定；实施前先验证现有适配器：当前 Agent 将每个 `usage` 事件相加，因此预算账本必须复用同一约定，并对每次请求避免重复记账。缺失或部分字段单独标记，不借用 `onUsage` 终态回调再次累计。
- 仅由 Rein 管理并正确继承上下文的子 run 在范围内。工具内部自行创建的 Agent、直接调用外部模型或 MCP 服务的消耗不自动计入。

## 4. 行为设计

### 4.1 传播与隔离

预算上下文由运行时显式携带，通过工具执行上下文传给 `createSubagentTool` 启动的子 run，不依赖 `AbortSignal` 对象身份。已有 signal 仍专门负责取消。实现时避免让一般工具无意中篡改账本：公开给宿主的快照应只读，内部写入通过受控接口完成。

嵌套子代理、多种工具实例以及父 run 没有提供 signal 时都继承同一账本；两个独立根 run 即便共享工具实例也不互相扣费。保留现有 `onUsage` 的单子 run 语义，避免重复记账。

### 4.2 模型调用次数：严格准入

- 可选配置 `maxModelCalls`，未配置表示不限制，仍可以统计。
- 每次模型请求前以同步、不可分割的方式检查并认领一个名额；同进程并行任务不能超过上限。此保证仅覆盖本进程和同一账本。
- 达到上限后阻止新的模型请求，并以明确的 `budget_exceeded` 原因结束受影响的 run；已经发出的模型请求不被该上限追溯取消。
- 根 run 在下一次需要模型调用时同样受限；不能仅把子代理预算不足当成普通工具错误后让父 run 无限重试。已启动的工具与模型请求如何完成，应在终态与文档中保持可观察。

### 4.3 token：事后统计的软上限

- 后续切片增加可选 `maxTotalTokens`：每次请求完成或失败时使用实际可获得的 usage 记账；达到或超过上限后阻止后续模型请求。
- 只计入 provider 报告的 `totalTokens`；不把缺失字段视为零，不在本批混用不同 tokenizer 的估算值。具体处理缺失用量的策略须在编码前定稿：推荐预算开启时返回明确的 `usage_unavailable` 停止原因并停止后续请求，仍保留已知数值与不完整标记。
- 请求发出前无法保证其最终用量；并行请求可能同时在飞，最终超额可达到这些请求的实际总用量。此上限是软上限，不承诺精确 token 或美元封顶。
- 已报告 usage 后又失败或取消，保留已报告的值；provider 未报告的部分标记未知。不能承诺账本覆盖服务端实际扣费。

### 4.4 暂停、恢复与兼容

- 审批暂停和 `max_turns` 可恢复快照需要保存预算配置与已认领次数、已知用量及完整性；同一 run 恢复时继续累计，不重置也不重复计数。
- 恢复快照作为不可信输入校验；宿主仍负责快照来源、授权、原子认领与防止重复恢复。旧版 `AgentRunState` 的迁移或拒绝规则在实施前明确并覆盖测试，不悄悄丢弃已有计数。
- 并行子 run 尚未结束时不能生成宣称完整的共享快照。先确定安全快照点与取消/等待策略；如果现有暂停机制无法安全捕获整棵任务树，第一版明确拒绝该组合并测试，不制造可恢复的错误快照。
- `budget_exceeded` 初版作为停止终态，不承诺可恢复；增加预算后恢复属于单独设计。兼容现有终态事件、trace 与不启用预算的调用者。
- 暂停事件不一定含最终 usage；不能用子 run 终态回调作为预算实施接缝。每次请求的记账与快照由运行时统一负责。

### 4.5 审批与工具安全前置检查

现有子代理工具标记为 `readOnly` 并默认免父层审批，但其子 Agent 可能使用有副作用的工具。此前文档称“不会放宽权限”过于笼统：子 Agent 的工具审批策略与父 Agent 独立，宿主配置不当可产生实际副作用。实施预算前应单独审查该权限边界、修正文档，并验证任何默认策略变更不会意外破坏现有用法；预算限制本身不能替代授权。

## 5. 待验证的接口草图

以下仅表达能力，字段名与类型在实现时结合现有事件模型定稿：

```ts
const agent = new Agent({ model, tools: [researcher] });

for await (const event of agent.stream({
  messages: [{ role: "user", content: "调研并比较方案" }],
  budget: { maxModelCalls: 12 },
})) {
  // 宿主可观察预算快照与停止原因。
}
```

- 宿主可以在根 run 输入上配置预算；子代理继承同一上下文，不要求每层手动传参。
- 外部可读取 `modelCalls`、已知 token 用量、完整性与限制值；既有 run `usage` 不改变含义。
- 暂停快照中的预算数据与公开的只读统计分开设计；不将内部可变账本直接暴露到可序列化接口。
- 是否新增 `agent.budget.updated` 事件或复用现有 `usage` 事件需在实现前根据 trace 和消费成本确定；无论选择哪种方式，终态都应暴露足够信息解释停止。

## 7. 第一批实施记录

- `Agent.stream` 支持 `budget.maxModelCalls`；父 run、经 `createSubagentTool` 启动的后代共用账本。`agent.budget.updated` 提供树级快照，既有 run 级 `usage` 和 `onUsage` 不变；trace 保留最近的预算快照。
- 审批与 `max_turns` 快照保存账本。旧版无账本快照可以恢复，但此前树用量无法重建，恢复后的 `usageComplete` 为 false；宿主必须保护快照来源并原子认领。
- `usageComplete` 为 false 包括字段缺失、模型请求尚未完成或异常中断，以及旧快照缺少历史账本。它只表明 Rein 是否观察到完整字段，不保证等同实际账单。请求失败仍计入调用次数。
- 安全审查：子代理的父层工具默认只读免审批，子代理自身的工具和审批独立；README 和阶段 B 计划已修正原有的过度安全承诺。并未改变默认权限策略。
- 适配器审查：Anthropic 在 `finalMessage()` 后发出一个包含 input/output/total 的 usage；OpenAI Chat Completions 在收到包含 usage 的 chunk 时发出 usage；OpenAI Responses 在 completed 或 incomplete 事件包含 usage 时发出 usage。所有事件沿用当前 Agent 的累加约定，异常或缺失时不推断真实费用。
- 边界：子 run 的暂停快照不会传回父 run，父代理只收到工具错误；账本检查点在其他模型请求进行中会拒绝创建。不可将此能力视为整棵并发任务树的持久化或恢复协议。

**A4–A5 实施记录**

- `budget.maxTotalTokens` 限制任务树已报告的总 token；达到上限时阻止后续模型请求，正在执行的请求仍可完成。模型调用次数与 token 上限可分别或共同设置。
- token 完整性单独记录为 `tokenUsageComplete`。模型请求失败、中断或未报告有效 `totalTokens` 时，已知用量仍累计；启用 token 预算后，下一次模型请求以 `usage_unavailable` 停止。其他字段缺失只影响 `usageComplete`。
- `max_turns` 恢复保留 token 限额和已知用量；此前只有调用次数预算的快照可继续恢复。两个停止原因及统计可通过事件和 trace 观察。
- 确定性测试覆盖超额、并行在途、缺失或无效 usage、子 run 失败、取消、无效配置以及恢复。README 说明了软上限、工具副作用和统计边界。

## 8. 关键决策与后续

建议先交付 A0–A3，再以 A4 作为独立切片。`maxModelCalls` 能严格限制同进程的准入数量；token 上限依赖 provider 用量和并发行为，不应包装成严格费用上限。

实施前需最终确定：

1. token usage 缺失时采用建议的停止策略，还是允许宿主选择继续并标记统计不完整。
2. 预算耗尽时，在终态暴露的结构和子 run/父 run 的状态如何表达；父 run 不能在共享预算耗尽后再调用模型。
3. 旧版快照的兼容方式，以及无法安全捕获并行子 run 时的明确行为。
4. 需要结果汇总的任务是否要为父 Agent 预留模型调用名额；第一版可先不支持预留，并明确预算用尽后无法保证最终自然语言总结。

待有具体业务需求后，再考虑共享美元估算、按代理分配子额度、工具费用、跨 run/进程持久化和预算用尽后的恢复。
